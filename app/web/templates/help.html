{# 1. About #}

1. О системе

Эта ERP создана специально для малого бизнеса. Здесь нет сотни ненужных функций — только то, что реально нужно для ежедневной торговли: учёт товаров, склады, приход, продажи, накладные и долги клиентов.

⚠️ Важно: для работы системы необходимо постоянное подключение к интернету. Все данные хранятся на вашем сервере и синхронизируются через браузер в режиме реального времени.
Структура верхнего меню: после продажных операций доступен раздел «Отчёты». Пункт «Документы» объединяет накладные и историю. Пункт «Справочники» объединяет бренды, клиентов и поставщиков. Раздел «Помощь» содержит руководство пользователя.
{# 2. Quick start #}

2. Быстрый старт — с чего начать

  1. Войдите в систему. Откройте браузер, перейдите по адресу вашего сервера. Если включена блокировка (site lock), введите пароль на странице «Войти».
  2. Создайте бренды. Перейдите в раздел Бренды и добавьте торговые марки товаров (например: Samsung, Artel, Sonifer).
  3. Добавьте товары. В разделе Товары создайте карточки для каждого продукта: укажите бренд, модель, название и штрих-код.
  4. Создайте склады. Склады создаются в разделе Приход: при создании нового прихода в поле «Склад назначения» выберите «+ Новый склад» и введите код и название (например: код MAIN, название «Основной склад»). После первого прихода склад становится доступен во всей системе.
  5. Добавьте клиентов. Перейдите в Клиенты и создайте карточки клиентов с именами и номерами телефонов.
  6. Оприходуйте товар. В разделе Приход создайте новую операцию, выберите склад и источник, добавьте товары с количеством и ценой закупки.
  7. Сделайте продажу. В разделе Продажа выберите клиента, добавьте товары, укажите цену продажи и завершите — система сформирует накладную.
  8. Следите за остатками. Раздел Склад показывает актуальные остатки по каждому товару и складу в реальном времени.
{# 3. Products #}

3. Товары

Каталог всех ваших продуктов. Каждый товар идентифицируется сочетанием «Бренд + Модель».

Что можно делать:

  • Добавить новый товар: кнопка «Добавить товар» — выберите бренд, укажите модель, название и штрих-код.
  • Редактировать товар: нажмите кнопку ✏️ напротив товара — можно изменить бренд, модель, название, штрих-код, цену прихода.
  • Архивировать товар: если товар больше не продаётся, его можно скрыть из списка (архивировать), не удаляя историю.
  • Поиск: используйте строку поиска по бренду/модели/названию.
  • Показать/скрыть архивные товары — переключатель в верхней части страницы.

Совет: называйте модели единообразно (например, всегда латиницей: SF-500), чтобы поиск работал точнее.

{# 4. Stock #}

4. Склад

Показывает текущие остатки товаров по каждому складу. Здесь нельзя напрямую изменить количество — остатки меняются только через операции: Приход, Перемещение, Продажа, Возврат.

  • Фильтрация по складу — выберите нужный склад в выпадающем списке вверху.
  • Скачать XLSX — получить текущие остатки в формате Excel.
  • В строке каждого товара видно: количество, цену закупки (wh_price) и итоговую стоимость остатка.

STK в правом верхнем углу навигации — это общая стоимость всех товаров на всех складах по цене закупки.

{# 5. Receive #}

5. Приход

Операция оприходования: товар поступает на склад от поставщика или из другого источника.

Пошагово:

  1. Нажмите «Новый приход».
  2. Выберите склад назначения (куда поступит товар).
  3. Выберите источник (поставщик, перемещение и т.д.).
  4. Нажмите «Добавить товар» и выберите из каталога нужный.
  5. Укажите количество и цену закупки (USD).
  6. Повторите для каждого товара в партии.
  7. Нажмите «Завершить» — остатки обновятся автоматически, будет создан документ XLSX.

Важно: цена закупки влияет на STK (стоимость склада) и на расчёт прибыли при последующей продаже.

{# 6. Move #}

6. Перемещение (Move / Move all)

Перемещение товара между складами.

  • Move — выбираете конкретный товар и количество для перемещения с одного склада на другой.
  • Move all — перемещает весь ассортимент (все позиции) с одного склада на другой. Удобно, если нужно «отправить всё из основного склада в магазин».

Совет: используйте Move all в начале рабочего дня для быстрого пополнения торговой точки.

{# 7. Sale #}

7. Продажа (Sale)

Создание накладной на продажу товара клиенту.

Пошагово:

  1. Выберите клиента из списка.
  2. Выберите склад, с которого продаёте.
  3. Нажмите «Добавить товар», выберите товар, укажите количество и цену продажи (USD).
  4. Повторите для всех позиций.
  5. Нажмите «Завершить» — накладная создана. Остатки снижены, долг клиента увеличен на сумму продажи.

После завершения продажи можно скачать накладную в XLSX или просмотреть в браузере.

DEB в правом верхнем углу навигации — суммарный долг всех клиентов по всем продажам.

{# 7a. Free (non-stock) position #}
Свободная позиция вне склада

Используется, когда товар физически есть в магазине, но он не заведён в ERP/склад (например, штучные или редкие товары, которые не нужно оформлять через приход).

Как добавить:

  1. На странице продажи введите название позиции вручную в поле поиска товара.
  2. Укажите количество.
  3. Укажите цену за единицу.
  4. Нажмите кнопку «Добавить вне склада» (или аналогичную кнопку добавления свободной позиции).

Что произойдёт:

  • Позиция появится в накладной.
  • Позиция будет включена в PDF и XLSX.
  • Сумма позиции добавится в долг клиента и общий DEB.

Что НЕ произойдёт:

  • Товар не будет списан со склада.
  • STK не изменится.
  • Товар не будет автоматически создан в справочнике товаров.
  • Приход не будет создан автоматически.

⚠️ Предупреждение: используйте свободную позицию только для товаров, которые действительно не ведутся в складском учёте. Для обычных складских товаров выбирайте товар из выпадающего списка — это обеспечивает правильное списание остатков.

{# 8. Return #}

8. Возврат (Return)

Оформление возврата товара от клиента. Товар возвращается обратно на склад, долг клиента уменьшается.

  1. Выберите клиента.
  2. Выберите склад, на который вернётся товар.
  3. Добавьте позиции и укажите количество для возврата.
  4. Завершите операцию — остатки пересчитаются, долг клиента скорректируется.
{# 8a. Reports #}

9. Отчёты

Раздел «Отчёты» — это первая рабочая версия базовой аналитики ERP.

Он показывает выручку, возвраты, чистую выручку, количество продаж, проданные товары, средний чек, количество товаров на складе, позиции с остатком, топ товаров, низкие остатки и выручку по дням за выбранный период.

Готовые периоды в фильтре автоматически заполняют даты С/По; если даты изменить вручную, период переключается на «Произвольный период». Вариант «За всё время» показывает отчёты от начала данных системы до текущей даты.

Фильтр «Склад» позволяет смотреть складские показатели и низкие остатки по всем складам, одному складу или нескольким выбранным складам. Выбор складов сохраняется в URL после применения фильтра и не сбрасывается при обновлении страницы. Фильтр склада применяется только к складским показателям и блоку низких остатков.

Раздел «Отчёты» ведёт к двум специализированным подотчётам: Отчёт по прибыли и Расхождения по инвентаризации. Ссылки на них также вынесены на страницу /reports.

{# 8b. Profit report #}
Отчёт по прибыли (/reports/profit)

Отдельная страница, показывающая, сколько бизнес заработал за период. Открывается по кнопке 📈 «Отчёт по прибыли» в разделе Отчёты или из верхнего меню.

Что показывает. Четыре KPI-карточки сверху:

  • Чистая выручка — продажи минус возвраты за выбранный период.
  • Себестоимость — сумма закупочных цен проданных товаров (без товаров, для которых цена закупки неизвестна — см. ниже).
  • Валовая прибыль = Чистая выручка − Себестоимость.
  • Маржа % = Валовая прибыль ÷ Чистая выручка × 100.

Затем идут три таблицы аналитики:

  • По брендам — выручка, себестоимость, прибыль и маржа по каждому бренду. Помогает понять, какие бренды приносят больше прибыли, а какие только выручку.
  • По клиентам — то же по клиентам. Показывает, какие клиенты приносят реальную прибыль, а не просто оборот.
  • Топ 20 товаров — самые прибыльные позиции за период.

Фильтры: период (С/По) и склад — можно смотреть прибыль по одному конкретному складу или по всем сразу.

⚠️ Жёлтая плашка «Нераскрытая себестоимость». Если в отчёте видите жёлтое предупреждение — оно указывает, на сколько строк и какую сумму выручки система не смогла посчитать себестоимость. Это нормально для старых продаж, сделанных до внедрения снимков цен закупки.

Такие строки исключены из расчёта себестоимости и прибыли — иначе они бы «завышали» валовую прибыль (казалось бы, товар продали, а закупки как будто не было). Со временем, по мере новых продаж, эта «нераскрытая» полоса будет уменьшаться.
{# 8b-1. Cost snapshots explanation #}
Как считается себестоимость (Cost snapshots)

При каждой новой продаже и возврате система запоминает цену закупки на момент операции — этот снимок хранится в самой строке накладной. Даже если позже цена закупки на карточке товара изменится (например, следующая партия пришла дороже), старая продажа сохранит свою историческую цену.

Это работает и при редактировании уже созданной накладной: если правите старую продажу, себестоимость её строк не перезаписывается новой ценой — она остаётся такой, какой была в день продажи. Только для новых позиций, добавленных при редактировании, берётся текущая цена закупки.

Почему часть строк с cost=0. Продажи, сделанные до внедрения снимков, не имеют записанной себестоимости — там 0. Мы намеренно не подставляем туда текущую цену закупки (это было бы неправдой). Такие строки видны как отдельная «нераскрытая» сумма на жёлтой плашке отчёта.

{# 8c. Inventory #}

10. Инвентаризация (/inventory)

Раздел для сверки того, что реально лежит на складе, с тем, что показывает система. Если во время физического пересчёта нашлись расхождения (недостача или излишек) — они фиксируются отдельными операциями ADJUST в журнале движений товара. История прошлых приходов, продаж и возвратов не меняется — только добавляются новые строки-корректировки.

Пошагово:

  1. Меню → Инвентаризация.
  2. Выберите склад.
  3. Выберите режим:
    • Полная сверка — таблица со всеми позициями склада для сплошного пересчёта.
    • Точечная сверка — та же таблица, но с полем поиска сверху для быстрого фильтра по бренду / модели / штрихкоду. Удобно, если пересчитываете только определённые товары.
  4. Для нужных строк впишите в колонку «Факт» реальное количество (то, что видите на полках). Пустые поля игнорируются — не обязательно проверять все позиции.
  5. Колонка «Разница» считается автоматически: зелёная +N (излишек), красная −N (недостача). Внизу таблицы появляется сводка «Заполнено строк / Оприходовано / Списано».
  6. Впишите комментарий (обязательно — например, «Ежемесячная инвентаризация 07.2026»).
  7. Нажмите «Применить корректировки» — подтвердите. Система создаст по одной ADJUST-операции на каждую строку с расхождением.

Сортировка колонок. Клик по заголовку — сортировка по возрастанию; повторный клик — по убыванию. Стрелка ▲/▼ показывает направление. Введённые в «Факт» значения сохраняются при пересортировке.

Аудит-корректно. Инвентаризация никогда не удаляет и не переписывает прошлые операции. Даже если случайно вписали не ту цифру и сохранили — правильный путь исправить это через повторную инвентаризацию с обратной корректировкой (с комментарием «откат ошибки»). В журнале останутся обе строки — это правильно и защищает от «зачистки следов».
{# 8c-1. Inventory discrepancies report #}
Отчёт расхождений (/reports/inventory)

Показывает, что происходило с инвентаризацией за выбранный период. Открывается кнопкой «Отчёт расхождений» на странице /inventory или через раздел Отчёты.

Что показывает:

  • 4 KPI-карточки: сумма оприходованного (+), сумма списанного (−), чистый эффект и общее количество ADJUST-операций.
  • По складам — сколько излишков/недостач и операций на каждом складе.
  • Товары с расхождениями — какие конкретно позиции чаще всего «уходят в ноль» или наоборот появляются лишними. Позволяет выявить проблемные товары (кражи, ошибки при отгрузке и т.п.).
  • Журнал — последние 200 ADJUST-операций с датой, складом, товаром, разницей и комментарием.

Фильтры: период (С/По) и склад.

{# 8d. Expenses #}

11. Расходы (/expenses)

Отдельный раздел для всех трат, которых нет в ERP через приход/ledger/склад: аренда, зарплата помощнику, налоги, коммуналка, интернет, реклама, транспорт — а также личные покупки. Оплаты поставщикам сюда не заносить: они уже учтены в приходах и себестоимости проданного товара.

Как работает:

  1. Меню → Расходы → «＋ Добавить расход».
  2. Укажите дату, категорию, сумму в USD и заметку. Сохранить.
  3. На главной странице раздела: фильтры (период, категория, тип, поиск), три KPI-карточки (Бизнес / Личное / Всего) и список за период. Каждую запись можно редактировать или удалить (с подтверждением).
Важно: оплаты поставщикам НЕ заносить в Расходы — иначе задвоится. Поставщик уже учтён в приходной накладной (влияет на себестоимость товара), а его оплата — в supplier_ledger (уменьшает долг перед ним). Если добавите те же 500$ ещё и как «Расход», финотчёт покажет минус, которого на самом деле нет.

Что заносить в Расходы:

  • Аренда магазина, склада, офиса
  • Зарплата помощнику, продавцу
  • Налоги, госторг, лицензии
  • Коммуналка (свет, вода), интернет, связь
  • Транспорт (бензин, такси для работы)
  • Реклама (Instagram, Telegram, листовки)
  • Услуги: грузчик, растаможка, ремонт оборудования
  • Личные покупки (телефон, одежда), семья
Категории расходов

Категории — это справочник, чтобы не писать «аренда», «Аренда», «Rent» по-разному и потом не искать. Каждая категория помечена одним из двух типов: 📦 Бизнес или 🛒 Личное. Тип используется в финотчёте — бизнес и личное считаются отдельно.

При первой установке в базе уже есть стандартный набор: Аренда, Зарплата, Налоги/Госторг, Коммуналка, Транспорт, Связь/Интернет, Реклама, Прочие бизнес — плюс Личные покупки, Семья, Прочие личные. Открыть Расходы → Категории, чтобы добавить свои (например «Реклама Instagram»), переименовать или отправить в архив.

Архив категории: архивированная категория не появляется в форме нового расхода, но продолжает считаться в отчётах и остаётся у уже существующих записей. Удалить категорию нельзя (иначе сломались бы старые записи).

Финотчёт (/reports/finance)

Ответ на вопрос «идёт ли торговля в плюс» — с учётом всех расходов. Открывается кнопкой «Финотчёт» на странице /reports или ссылкой из раздела Расходы.

Структура отчёта:

  1. 📦 Торговля — те же цифры, что в Отчёте по прибыли: Чистая выручка, Себестоимость, Валовая прибыль, Маржа %.
  2. 🛠️ Доход от услуг — таблица по категориям (ремонт ПК, PlayStation, установка ПО и т.п.) и итог. Показывается отдельной строкой, чтобы не смешиваться с торговой выручкой — торговая маржа остаётся чистой.
  3. = Итого доход — Валовая прибыль + Доход от услуг. Общая сумма, которую заработал бизнес за период (товары + услуги).
  4. 💼 Бизнес-расходы — таблица по категориям (аренда, зарплата и т.д.) и итоговая сумма.
  5. = Чистая прибыль бизнеса — главная цифра: Итого доход − Бизнес-расходы. Именно она показывает, зарабатывает бизнес или проедает деньги.
  6. 🛒 Личные расходы — таблица по категориям и итог. Показывается отдельно, чтобы личные траты не искажали финрез торговли.
  7. = Итог кошелька — Чистая прибыль бизнеса − Личные расходы. Реальный остаток от бизнеса на руках за период.

Фильтры: период (по умолчанию — текущий месяц) и склад. Фильтр склада применяется только к «Торговле» — расходы не привязаны к складу.

⚠️ Про «Нераскрытую себестоимость». Если в Отчёте по прибыли есть жёлтая плашка о cost=0 строках — эта же сумма выручки не входит в Валовую прибыль здесь, и значит не участвует в расчёте Чистой прибыли бизнеса. Финотчёт показывает подсказку с количеством и суммой таких строк, если они есть.
{# 8e. Service incomes #}

11a. Доходы от услуг (/incomes)

Отдельный раздел для денег, которые бизнес зарабатывает не на продаже товара, а на услугах: ремонт ПК, ремонт PlayStation, установка антивируса/ПО, запись игр, прошивка/чиповка и т.п.

Зачем отдельно от продаж? Услуги не имеют себестоимости, и если засунуть их в продажи товара — маржа взлетит до потолка и перестанет показывать, работает ли торговля в плюс. Поэтому Доходы от услуг живут отдельно и не смешиваются с торговой выручкой и торговой маржой. В финотчёте они видны отдельной строкой «🛠️ Доход от услуг» и складываются с Валовой прибылью в «Итого доход».

Как работает:

  1. Меню → Доходы → «＋ Добавить доход».
  2. Дата, услуга (категория), валюта (по умолчанию TMT), сумма, заметка. Сохранить.
  3. На главной странице раздела — фильтры (период, категория, поиск), KPI «Всего за период» и «Топ услуга», список с бейджем 🤖 Telegram для записей из бота.

Категории по умолчанию: Антивирус/ПО, Ремонт ПК, Ремонт PlayStation, Запись игр, Прошивка/чиповка, Прочие услуги. Свои категории (например «Настройка роутера») добавляй в Доходы → Категории. Категорию с записями удалить нельзя — только в архив (как в Расходах).

TMT-манат: валюта по умолчанию — TMT. Курс TMT→USD берётся из настройки «Pocket Price TMT rate» в момент создания записи и больше никогда не пересчитывается. Изменил курс через месяц — старые записи стоят по своему историческому курсу.

Что заносить в Доходы:

  • Ремонт компьютеров, ноутбуков, планшетов
  • Ремонт PlayStation, приставок
  • Установка/переустановка Windows, антивируса
  • Запись игр, прошивка/чиповка
  • Настройка роутера/Wi-Fi, консультации
  • Любая другая услуга без продажи товара клиенту
Не путать с продажей товара. Если клиент купил у тебя жёсткий диск и попросил установить Windows на него — жёсткий диск идёт через обычную Продажу (там маржа), а работа установки — в Доходы от услуг. Так торговая маржа остаётся точной, а доход от услуги видно отдельной строкой.
{# 9. Brands #}

12. Бренды

Справочник торговых марок. Раздел доступен из выпадающего меню «Справочники». Каждый товар должен принадлежать бренду.

  • Добавить бренд: укажите название (например, «Artel» или «Xiaomi»).

{# 10. Clients #}

13. Клиенты

Справочник покупателей. Раздел доступен из меню «Справочники». Здесь хранится информация о каждом клиенте и его текущий долг.

Типы клиентов и табы. Клиенты делятся на две категории, которые видны как вкладки наверху страницы:

  • 📦 Оптовики — компании, магазины, перекупщики, которые закупают товар крупными партиями.
  • 🛒 Штучные — соседи, знакомые, частные покупатели, которые берут товар поштучно «до зарплаты».
  • Все — общий список с обоими типами. Рядом с именем виден бейдж 📦 или 🛒.

При создании нового клиента выберите тип в форме «Добавить клиента». Поменять тип можно в любой момент через «Изменить». Тип никак не влияет на ценообразование — это просто способ организовать список.

Запоминание фильтра. Выбранная вкладка, сортировка и строка поиска запоминаются в браузере на год. Когда заходите в историю клиента и возвращаетесь — фильтр восстанавливается.

Действия:

  • Добавить клиента: имя, номер телефона, заметка, тип.
  • Редактировать: изменить имя, телефон, заметку, тип.
  • Долг клиента (Debt USD) — сумма неоплаченных накладных. Изменяется автоматически при продаже и возврате.
  • «Снять с долга» / «Добавить долг» — ручная корректировка баланса с подтверждением.
  • История — все продажи, возвраты и корректировки. Записи типа «Оплата» можно удалить (например, если случайно нажали два раза).
  • Архивировать клиента — скрыть неактивного клиента, не удаляя историю.
{# 10a. Payment discipline #}
Дисциплина платежей

Чтобы не приходилось помнить, кто и когда платил в последний раз, система показывает подсказки прямо в списке клиентов и в истории каждого клиента.

Бейджи в списке клиентов. В колонке «Последняя оплата» у каждого клиента с долгом виден бейдж:

  • 🟥 Красный — последняя оплата более 30 дней назад (или её вообще не было при наличии долга).
  • 🟨 Жёлтый — последняя оплата от 14 до 30 дней назад.
  • Без бейджа — платят регулярно (≤14 дней) или долга нет.

Цвет учитывает только клиентов с текущим долгом — если клиент не должен, красный/жёлтый бейдж не появится.

Сортировка «Давно не платили». В сортировке списка появился вариант «Давно не платили» — клиенты, у которых больше всего дней тишины при наличии долга, поднимаются наверх. Удобно для утреннего обхода/обзвона.

4 карточки в истории клиента. Открыв историю конкретного клиента, сверху увидите:

  • Последняя оплата — дата последнего платежа (или «не было»).
  • Дней тишины — сколько дней прошло с последней оплаты. У честного плательщика — маленькое число, у «зависшего» — большое.
  • Оплачено за 30 дней — сколько клиент внёс за последний месяц. Показывает недавнюю активность.
  • Средний платёж за 90 дней — средний размер оплаты по последним 3 месяцам. Понимание, каким кусочком клиент обычно закрывает долг.
{# 11. Suppliers #}

14. Поставщики

Справочник поставщиков доступен из выпадающего меню «Справочники». Здесь хранится информация о поставщиках и текущий долг перед ними в USD.

  • Добавить поставщика: имя, телефон и заметка.
  • Баланс поставщика (Debt USD) считается как сумма завершённых приходных накладных минус сумма оплат и корректировок в журнале поставщика.
  • Чтобы уменьшить долг, откройте карточку поставщика и добавьте оплату/корректировку; при необходимости можно добавить долг вручную.
  • Архив/разархив: неактивного поставщика можно архивировать и вернуть из архива позже без потери истории.
  • В истории поставщика видны приходы, оплаты и баланс после каждой операции.
{# 12. Invoices #}

15. Накладные (Invoices)

Список всех созданных документов: накладные продажи и возвраты. Раздел доступен из меню «Документы».

  • Просмотр: нажмите «Просмотреть» рядом с накладной — откроется страница с деталями.
  • Скачать XLSX: получить накладную в формате Excel для печати или передачи клиенту.
  • Отменить накладную: если продажа не состоялась после создания накладной, можно отменить её. Товар вернётся на склад, долг клиента уменьшится.
  • Фильтрация по клиенту или дате для быстрого поиска нужной накладной.
{# 13. History #}

16. История (History)

Полный журнал всех движений товаров: приходы, продажи, возвраты. Раздел доступен из меню «Документы» и позволяет отследить любую операцию.

  • Поиск по ключевому слову (бренд, модель, номер накладной, клиент).
  • Для каждой записи указано: дата/время, тип операции, товар, количество, цена, склад, контрагент.
  • Скачать XLSX или просмотреть документ прямо из истории.

17. Настройки (Admin)

Системные настройки и управление ERP.

  • Блокировка сайта (Site Lock): включить пароль для входа. Рекомендуется, если сервер доступен из интернета.
  • Язык интерфейса по умолчанию: EN / RU / TM.
  • Тема: светлая, тёмная или системная.
  • Фон: включить/выключить фоновое изображение, настроить затемнение.
  • Резервная копия: создать или восстановить резервную копию базы данных.
  • Токены (Price / Catalog): для доступа к публичному прайс-листу без пароля (для клиентов).

{# 14a. Sale markup presets #}
Проценты продажи — настройка наценок

В разделе Admin → Проценты продажи можно выбрать, какие кнопки процентов отображаются на странице /sale, и задать процент по умолчанию.

Что настраивается:

  • Активные проценты: отметьте нужные из вариантов 5%, 10%, 15%, 20%, 25%, 30% — отмеченные кнопки будут показаны на странице продажи.
  • Процент по умолчанию: тот процент, который автоматически выбран при открытии новой продажи. Должен быть в числе активных.

Как это работает на странице продажи:

  • Отображаются только включённые проценты.
  • Процент по умолчанию уже активен при открытии страницы.
  • Кнопка Вручную доступна всегда — позволяет ввести любую цену вручную.
⚠️ Важно: изменение активных процентов и процента по умолчанию не пересчитывает старые накладные и уже сохранённые цены. Новый процент применяется только при добавлении новой позиции в продажу.
{# 15. Pocket Price #}

18. Pocket Price — публичный прайс-лист

Pocket Price — облегчённая страница просмотра актуальных цен и остатков. Она предназначена для клиентов или сотрудников, которым нужно быстро узнать цену без доступа к основному ERP.

Как открыть:

  • Страница доступна по ссылке /price?token=<токен>.
  • Токен создаётся в Admin → Токены Price: нажмите «Создать токен», скопируйте ссылку и передайте клиенту или сотруднику — пароль ERP не требуется.

Что умеет:

  • Поиск товара по названию, модели или штрих-коду.
  • Сканирование штрих-кода камерой телефона (требуется HTTPS).
  • Отображение цены продажи; опционально — количество в наличии и цена закупки (настраивается для каждого токена).
  • Работает как PWA: можно «установить» на главный экран смартфона.

Безопасность: любой, у кого есть ссылка, может просматривать прайс — не передавайте токен посторонним. Отозвать или удалить токен можно в Admin → Токены Price.

{# 16. Pocket Catalog #}

19. Pocket Catalog — мобильный каталог

Pocket Catalog — PWA-приложение для работы с каталогом товаров прямо на складе. Сотрудник сканирует штрих-коды и обновляет цены закупки, не заходя в основной интерфейс ERP.

Как открыть:

  • Страница доступна по ссылке /catalog?token=<токен>.
  • Токен создаётся в Admin → Токены Catalog.
  • При первом открытии ссылки устройство привязывается к токену — повторная авторизация не нужна, однако другое устройство с тем же токеном работать не будет (защита от утечки).

Что умеет:

  • Поиск товара по штрих-коду: ручной ввод, сканирование камерой телефона или аппаратный Bluetooth/USB HID-сканер.
  • Просмотр карточки товара: бренд, модель, название, остатки.
  • Обновление цены закупки прямо из каталога.
  • Добавление нового товара в каталог без входа в основной ERP.

Аппаратный сканер штрих-кодов: Pocket Catalog может работать с внешним сканером, если он подключается к телефону как клавиатура — Bluetooth HID / Keyboard mode. Поставьте курсор в поле ввода штрих-кода, отсканируйте товар — сканер введёт код в поле. Если в сканере включён суффикс Enter, Pocket Catalog обработает код автоматически; без суффикса нажмите кнопку → вручную.

Рекомендации по выбору сканера:

  • Для телефона выбирайте Bluetooth HID / Keyboard mode.
  • Сканеры только 2.4G USB чаще удобнее для ПК и могут потребовать USB-приёмник или OTG-переходник.
  • Рекомендуемый вариант: 2D Bluetooth HID-сканер.
  • Желательные поддерживаемые коды: EAN-13, EAN-8, UPC, Code128, а также QR / DataMatrix для универсальности.
  • Суффикс Enter удобен, но не обязателен — без него можно нажать кнопку → вручную.

Типичный сценарий: сотрудник на складе сканирует поступивший товар, смотрит остатки и обновляет закупочную цену, не отвлекая менеджера на компьютере.

Безопасность: токен привязан к конкретному устройству. Для смены устройства или отзыва доступа используйте Admin → Токены Catalog.

20. Telegram-бот

⚠️ Только для вэб-версии. Бот работает вместе с этой серверной вэб-версией ERP. В десктопной версии HASAPCY бота нет — она работает автономно на компьютере клиента, без интернета и без Telegram.

Бот сделан под одну задачу — быстро работать с долгами клиентов на ходу, когда стоишь у клиента с телефоном в руке. Товары, склад, приход, продажи в бота не входят — всё это удобнее в вэб.

Команды:

  • /start — главное меню: недавние клиенты (кто платил за последние 7 дней) + кнопки поиска, топ должников, «💸 Расход» и «💵 Доход»
  • /clients — то же самое, что /start
  • /debt — сколько мне вообще должны в сумме
  • /top_debtors — топ-10 должников с пометкой «сколько дней без оплаты»
  • /expense — визард быстрого расхода (бензин, грузчик, аренда, личное…)
  • /expenses_today — сколько потратил сегодня (сводка по категориям)
  • /income — визард быстрого дохода от услуги (ремонт ПК, PlayStation, установка ПО…)
  • /income_today — сколько заработал на услугах сегодня
  • /help — короткая шпаргалка
  • /cancel — отменить текущий шаг

Обычный сценарий «в поле» — 3 тапа:

  1. Открыл бота → тап по имени клиента из списка недавних (или «🔍 Поиск» → часть имени → тап).
  2. В карточке клиента (имя, долг, телефон, последние 3 операции) тап по кнопке быстрой оплаты [💵 50], [💵 100], [💵 200] или [💵 500]. Для другой суммы — «Другая оплата» → напиши цифру.
  3. Подтверди — «✅ Да, списать». Готово.

Добавление долга:

  1. В карточке клиента тап «➕ Добавить долг».
  2. Пишешь сумму.
  3. Пишешь заметку — обязательно (причина: «взял в долг товар», «предоплата не пришла»). Без заметки бот не даст сохранить, чтобы потом не гадать за что этот долг.
  4. Подтверди — «✅ Да, добавить долг».

Заметки к операциям (как в вэб):

  • Оплата — заметка не обязательна, поэтому бот вообще не спрашивает (быстрее).
  • Добавление долга — заметка обязательна (объясняет причину).

Расходы через бота (/expense): тап «💸 Расход» из главного меню или команда /expense → выбор категории (📦 бизнес / 🛒 личное) → сумма (по умолчанию TMT, тумблер на USD) → заметка (или «Пропустить») → экран подтверждения с текущим курсом → «✅ Применить». Через /expenses_today — сводка за сегодня. Курс TMT фиксируется в момент подтверждения и потом не пересчитывается.

Доходы от услуг через бота (/income): тап «💵 Доход» или /income → выбор услуги (Ремонт ПК, PlayStation, Антивирус/ПО…) → сумма (TMT/USD) → заметка → «✅ Внести доход». Через /income_today — сводка за сегодня. Доход от услуг попадает отдельной строкой в финотчёт и не смешивается с торговой маржой.

Связь с вэб: любая операция из бота — та же запись в БД, что при работе через вэб. Долг клиента, DEB в шапке, история клиента, /expenses, /incomes, финотчёт — всё обновляется мгновенно. В таблицах расходов/доходов записи из бота помечены бейджем 🤖 Telegram в отдельной колонке «Источник».

Кто может пользоваться: только владелец (по ADMIN_ID в конфиге сервера). Если кто-то посторонний найдёт бот и напишет /start — получит «Доступ запрещён».

Что бот НЕ умеет специально: добавлять товары, приходы, склад, продажи, накладные, отчёты, инвентаризацию. Всё это уже отлично работает в вэб — дублировать нет смысла. Через мобильный тап-экран сложные формы с товарами и ценами — только мучение.

{# 8b. Profit report #}
Peýda hasabaty (/reports/profit)

Işewürligiň saýlanan döwürde näçe gazanandygyny görkezýän aýratyn sahypa. Hasabatlar bölümindäki 📈 «Peýda hasabaty» düwmesi arkaly açylýar.

Näme görkezýär. Ýokarda 4 KPI-kart:

  • Arassa girdeji — döwrüň satyşlary minus yzyna gaýtarmalar.
  • Özüne düşýän gymmat — satylan harytlaryň satyn alyş bahalarynyň jemi (satyn alyş bahasy näbelli bolan harytlar hasaba alynmaýar — aşakda düşündirilýär).
  • Umumy peýda = Arassa girdeji − Özüne düşýän gymmat.
  • Marja % = Umumy peýda ÷ Arassa girdeji × 100.

Soň üç analitika tablisasy:

  • Brendler boýunça — her brendiň girdejisi, özüne düşýän gymmaty, peýdasy we marjasy. Haýsy brendleriň diňe aýlanyşyk däl, hakyky peýda getirýändigini görkezýär.
  • Müşderiler boýunça — şol bir zat müşderiler boýunça. Kim hakyky peýda getirýär, kim diňe dolanyşyk.
  • Iň gowy 20 haryt — döwrüň iň girdejili harytlary.

Süzgüçler: döwür (Başlangyç/Sonky) we ammar — bir belli ammar boýunça ýa-da hemmesi boýunça peýda görüp bolýar.

⚠️ Sary duýduryş «Näbelli özüne düşýän gymmat». Hasabatda sary duýduryş görseňiz — ol näçe setire we näçe girdejä ulgamyň özüne düşýän gymmaty hasaplap bilmedigini görkezýär. Bu satyn alyş bahasy snapshotlary girizilmezden öňki köne satyşlar üçin adaty ýagdaý.

Şeýle setirler hasaplamalardan çykarylýar — bolmasa umumy peýdany «göterip» galdyrardylar (haryt satyldy, satyn alyş ýok ýaly bolar). Wagt geçdigiçe, täze satyşlar bilen «näbelli» zolak kiçelýär.
{# 8b-1. Cost snapshots explanation #}
Özüne düşýän gymmat nähili hasaplanýar (Cost snapshots)

Her täze satyş we yzyna gaýtarmada ulgam şol wagtky satyn alyş bahasyny ýatda saklaýar — bu snapshot hasap-fakturanyň setiriniň özünde saklanýar. Soňra harytdaky satyn alyş bahasy üýtgese-de (meselem, indiki tapgyr gymmatrak geldi), köne satyş öz taryhy bahasyny saklaýar.

Bu köne hasap-fakturany redaktirlemekde-de işleýär: köne satyşy düzedeniňizde, onuň setirleriniň özüne düşýän gymmaty üýtgemeýär — satyş gününde nähili bolan bolsa, şeýle galýar. Diňe redaktirlemede täze goşulan setirler üçin häzirki satyn alyş bahasy alynýar.

Näme üçin käbir setirlerde cost=0. Snapshotlar girizilmezden öň edilen satyşlarda özüne düşýän gymmat ýazylmadyk — ol 0. Biz oňa häzirki satyn alyş bahasyny goýmaýarys (bu ýalan bolardy). Şeýle setirler hasabatdaky sary duýduryşda «näbelli» jem hökmünde görkezilýär.

{# 1. About #}

1. About the system

This ERP was built specifically for small business. There are no hundreds of unnecessary features here — only what is genuinely needed for everyday trading: product catalogue, warehouses, receiving stock, sales, invoices, and client debt tracking.

⚠️ Important: a permanent internet connection is required for the system to work. All data is stored on your server and synchronised through the browser in real time.
Top menu structure: the Reports section now appears after sales operations. Documents groups Invoices and History. Directories groups Brands, Clients, and Suppliers. The Help section contains the user manual.
{# 2. Quick start #}

2. Quick start — where to begin

  1. Log in. Open a browser and navigate to your server address. If site lock is enabled, enter the password on the «Login» page.
  2. Create brands. Go to the Brands section and add the trade marks of your products (e.g. Samsung, Artel, Sonifer).
  3. Add products. In the Products section, create a card for each product: set the brand, model, name and barcode.
  4. Create warehouses. Warehouses are created in the Receive section: when starting a new receive operation, select «+ New warehouse» in the «Destination warehouse» field and enter a code and name (e.g. code MAIN, name «Main warehouse»). Once the first receive is completed the warehouse becomes available throughout the system.
  5. Add clients. Go to Clients and create client cards with names and phone numbers.
  6. Receive stock. In the Receive section create a new operation, choose the destination warehouse and source, then add products with quantity and purchase price.
  7. Make a sale. In the Sale section choose the client, add products, set the sale price and finish — the system will generate an invoice.
  8. Monitor stock levels. The Stock section shows live balances for every product and warehouse.
{# 3. Products #}

3. Products

A catalogue of all your products. Each product is identified by the combination «Brand + Model».

  • Add a product: click «Add product» — choose a brand, enter model, name and barcode.
  • Edit a product: click the ✏️ button — you can change brand, model, name, barcode and purchase price.
  • Archive a product: if a product is no longer sold, hide it from the list without deleting its history.
  • Search: use the search bar to filter by brand/model/name.
  • Show/hide archived products — toggle at the top of the page.

Tip: name models consistently (e.g. always in Latin script: SF-500) so that search results are accurate.

{# 4. Stock #}

4. Stock

Shows current stock balances per warehouse. You cannot change quantities directly here — balances are updated only through operations: Receive, Move, Sale, Return.

  • Filter by warehouse — choose the required warehouse from the dropdown at the top.
  • Download XLSX — export current balances to Excel.
  • Each row shows: quantity, purchase price (wh_price) and total stock value.

STK in the top-right navigation bar is the total value of all stock across all warehouses at purchase price.

{# 5. Receive #}

5. Receive

Stock intake operation: goods arrive at a warehouse from a supplier or another source.

Step by step:

  1. Click «New Receive».
  2. Choose the destination warehouse (where the goods will go).
  3. Choose the source (supplier, transfer, etc.).
  4. Click «Add product» and select from the catalogue.
  5. Enter the quantity and purchase price (USD).
  6. Repeat for each item in the batch.
  7. Click «Finish» — stock balances update automatically and an XLSX document is created.

Important: the purchase price affects STK (stock value) and profit calculation on subsequent sales.

{# 6. Move #}

6. Move / Move all

Move stock between warehouses.

  • Move — choose a specific product and quantity to move from one warehouse to another.
  • Move all — moves the entire assortment (all items) from one warehouse to another. Useful when you need to «send everything from the main warehouse to the shop».

Tip: use Move all at the start of a working day to quickly restock a point of sale.

{# 7. Sale #}

7. Sale

Create a sales invoice for a client.

  1. Choose a client from the list.
  2. Choose the warehouse you are selling from.
  3. Click «Add product», select the product, set quantity and sale price (USD).
  4. Repeat for all line items.
  5. Click «Finish» — the invoice is created. Stock decreases; client debt increases by the invoice total.

After finishing you can download the invoice as XLSX or view it in the browser.

DEB in the top-right navigation bar is the total outstanding debt of all clients.

{# 7a. Free (non-stock) position #}
Free position (non-stock item)

Use this when a product is physically available in the shop but is not registered in the ERP/warehouse (e.g. one-off or rare items that do not need to be processed through a receive operation).

How to add:

  1. On the sale page, type the item name manually in the product search field.
  2. Enter the quantity.
  3. Enter the unit price.
  4. Click the «Add outside warehouse» button (or the equivalent free-position button).

What will happen:

  • The line item will appear in the invoice.
  • It will be included in the PDF and XLSX.
  • The amount will be added to the client's debt and the total DEB.

What will NOT happen:

  • The product will not be deducted from any warehouse stock.
  • STK will not change.
  • The product will not be automatically created in the product directory.
  • No receive operation will be created automatically.

⚠️ Warning: use a free position only for items that are genuinely not tracked in the warehouse. For regular warehouse products, always select the item from the drop-down list to ensure correct stock deduction.

{# 8. Return #}

8. Return

Process a product return from a client. The goods go back into the warehouse; client debt decreases.

  1. Choose the client.
  2. Choose the warehouse the goods will return to.
  3. Add line items and specify the return quantity.
  4. Finish the operation — balances are recalculated and client debt is adjusted.
{# 8a. Reports #}

9. Reports

The Reports section is now the first working version of basic ERP analytics.

It shows revenue, returns, net revenue, sales count, sold units, average receipt, units in stock, positions in stock, top products, low stock, and daily revenue for the selected period.

Preset periods automatically fill the From/To dates; if you edit either date manually, the period switches to Custom period. The All time option shows reports from the beginning of system data to the current date.

The Warehouse filter lets you review stock metrics and low stock for all warehouses, one warehouse, or multiple selected warehouses. The selection is persisted in the URL after applying the filter and stays selected after page refresh. The warehouse filter applies only to stock metrics and low-stock data.

The Reports section leads to two specialised sub-reports: Profit report and Inventory discrepancies. Direct links are also placed on /reports.

{# 8b. Profit report #}
Profit report (/reports/profit)

A dedicated page that shows how much the business earned over a period. Opens via the 📈 «Profit report» button in the Reports section or from the top menu.

What it shows. Four KPI cards at the top:

  • Net revenue — sales minus returns for the selected period.
  • Cost — total purchase price of sold items (excluding items whose purchase price is unknown — see below).
  • Gross profit = Net revenue − Cost.
  • Margin % = Gross profit ÷ Net revenue × 100.

Then three analytical tables:

  • By brand — revenue, cost, profit and margin per brand. Reveals which brands generate real profit versus just turnover.
  • By client — the same broken down per client. Shows who brings real profit rather than volume.
  • Top 20 products — the most profitable positions for the period.

Filters: period (From/To) and warehouse — you can look at profit for a single warehouse or all of them combined.

⚠️ Yellow «Unknown cost» notice. If the report shows a yellow warning — it tells you how many lines and how much revenue the system could not compute cost for. This is normal for old sales made before cost snapshots were introduced.

Those lines are excluded from the cost and profit calculation — otherwise they would inflate the gross profit (revenue with no matching purchase cost). Over time, as new sales are made, this «unknown» band shrinks.
{# 8b-1. Cost snapshots explanation #}
How cost is computed (cost snapshots)

On every new sale and return the system freezes the purchase price at the moment of the operation — this snapshot is stored on the invoice line itself. Even if the product's purchase price later changes on the product card (e.g. the next batch arrives at a higher price), the old sale keeps its historical cost.

This also works when editing an already-created invoice: when you fix an old sale, the cost on its existing lines is not overwritten with the new price — it stays as it was on the day of the sale. Only newly added lines during editing pick up the current purchase price.

Why some lines have cost=0. Sales made before snapshots were introduced don't have a recorded cost — it is 0. We deliberately do not backfill them with the current purchase price (that would be untrue). Such rows are shown as the separate «unknown» sum in the yellow banner of the report.

{# 8c. Inventory #}

10. Inventory (/inventory)

A section for reconciling what is physically in the warehouse with what the system says. If discrepancies are found during a physical count (shortage or surplus), they are recorded as separate ADJUST operations in the stock movement journal. Past receive, sale and return history is not modified — only new adjustment rows are appended.

Step by step:

  1. Menu → Inventory.
  2. Select a warehouse.
  3. Select a mode:
    • Full count — a table with every position on the warehouse for a complete recount.
    • Spot check — the same table but with a search field on top for quick filtering by brand / model / barcode. Handy if you're only recounting certain items.
  4. For the rows you want, type the real quantity into the «Actual» column (what you see on the shelves). Empty fields are ignored — you don't have to check every position.
  5. The «Δ» column is computed automatically: green +N (surplus), red −N (shortage). A summary line «Filled rows / Surplus / Shortage» appears below the table.
  6. Enter a comment (required — e.g. «Monthly inventory 07/2026»).
  7. Click «Apply adjustments» — confirm. The system creates one ADJUST operation per discrepancy row.

Column sorting. Click a header to sort ascending; click again for descending. The ▲/▼ arrow shows the direction. Values already entered into «Actual» are preserved when the rows are re-ordered.

Audit-safe. Inventory never deletes or overwrites past operations. Even if you accidentally save the wrong number — the correct way to fix it is a second inventory with a reverse adjustment (comment: «rollback of error»). Both rows will remain in the journal — that is correct and protects against covering up mistakes.
{# 8c-1. Inventory discrepancies report #}
Discrepancy report (/reports/inventory)

Shows what happened during inventory over a chosen period. Opens via the «Discrepancy report» button on the /inventory page or through the Reports section.

What it shows:

  • 4 KPI cards: total surplus (+), total shortage (−), net effect and total number of ADJUST operations.
  • By warehouse — how much surplus/shortage and how many operations per warehouse.
  • Products with discrepancies — which positions most often «disappear» or, conversely, come up as extras. Helps identify problem items (theft, shipping errors, etc.).
  • Journal — last 200 ADJUST operations with date, warehouse, product, delta and comment.

Filters: period (From/To) and warehouse.

{# 8d. Expenses #}

11. Expenses (/expenses)

Section for all spending that doesn't go through the ERP via receive/ledger/stock: rent, salary, taxes, utilities, ads, transport — and personal purchases. Payments to suppliers do not belong here: they're already accounted for in receive invoices and cost of goods sold.

How it works: Expenses → «＋ Add expense» → date, category, USD amount, note → Save. The list has filters (period, category, kind, search) and three KPI cards (Business / Personal / Total).

Important: don't record supplier payments here — they'd be double-counted. Those are already tracked via supplier_ledger.

Categories are tagged as 📦 Business (rent, salary, tax, ads, etc.) or 🛒 Personal (phone, clothes, family). The tag is used in the finance report — business and personal are counted separately. Manage your own categories at Expenses → Categories.

Finance report (/reports/finance)

Answers «is the trading profitable?» taking all expenses into account. Open via the Finance report button on /reports.

Structure:

  1. 📦 Trading — same numbers as Profit report (Net revenue, Cost, Gross profit, Margin %).
  2. 🛠️ Service income — table by category and total. Kept separate from trading revenue so it never dilutes the trading margin.
  3. = Total income — Gross profit + Service income.
  4. 💼 Business expenses — table by category and total.
  5. = Business net profit — the key number: Total income − Business expenses.
  6. 🛒 Personal expenses — separate table.
  7. = Wallet net — Business net profit − Personal expenses.

Filters: period (defaults to current month) and warehouse (only affects the Trading section).

{# 8e. Service incomes #}

11a. Service incomes (/incomes)

Separate section for money earned outside of product sales: PC repair, PlayStation repair, antivirus/software install, game recording, chipping and so on.

Why kept separate? Services have no cost of goods sold. If you mixed them into product sales, margin would jump to the ceiling and stop telling you whether trading is actually profitable. Service incomes therefore live on their own and are shown as a dedicated «🛠️ Service income» line in the finance report — never mixed with trading revenue or margin.

How it works: Incomes → «＋ Add income» → date, service (category), currency (defaults to TMT), amount, note → Save. TMT/USD rate is snapshotted at creation from the «Pocket Price TMT rate» setting and never re-computed later.

Default categories: Antivirus/Software, PC repair, PlayStation repair, Game recording, Chipping/firmware, Other services. Manage your own at Incomes → Categories.

{# 9. Brands #}

12. Brands

A directory of trade marks. This section is available from the Directories dropdown. Every product must belong to a brand.

  • Add a brand: enter the name (e.g. «Artel» or «Xiaomi»).
  • Edit a brand name.
  • Delete a brand — only possible if no products are linked to it.

Tip: create brands before adding products — otherwise the brand dropdown will be empty.

{# 10. Clients #}

13. Clients

A directory of buyers. This section is available from the Directories dropdown and stores each client's details and their current outstanding debt.

Client types and tabs. Clients are split into two categories visible as tabs at the top:

  • 📦 Wholesale — businesses, shops, resellers who buy in bulk.
  • 🛒 Retail — neighbours, friends, individual customers who buy small quantities «until next paycheck».
  • All — combined list. A 📦 or 🛒 badge appears next to each name.

Pick the type when adding a new client. You can change it any time via «Edit». Type does not affect pricing — it is purely an organisational tag.

The selected tab, sort and search text are remembered in your browser for a year, so you don't lose your filter when navigating in and out of the section.

Actions:

  • Add a client: name, phone, note, type.
  • Edit: change name, phone, note, type.
  • Debt USD — sum of unpaid invoices. Updates automatically on sale and return.
  • «Remove debt» / «Add debt» — manual balance adjustments with confirmation.
  • History — sales, returns and adjustments. «Payment» entries can be deleted (e.g. an accidental double-click).
  • Archive a client — hide an inactive client without deleting history.
{# 10a. Payment discipline #}
Payment discipline

So you don't have to remember who last paid and when, the system surfaces this right in the client list and in each client's history.

Badges in the client list. In the «Last payment» column each client with an outstanding debt shows a badge:

  • 🟥 Red — last payment more than 30 days ago (or no payment at all while a debt exists).
  • 🟨 Yellow — last payment 14–30 days ago.
  • No badge — pays regularly (≤14 days) or has no debt.

The colour is applied only to clients with a current debt — clients with no debt never get a red/yellow badge.

«Silent for longest» sort. A new sort option «Silent for longest» pushes clients with the largest gap since last payment (and a non-zero debt) to the top. Handy for a morning call-round.

4 cards on the client history. Opening a specific client's history you'll see at the top:

  • Last payment — date of the last payment (or «none»).
  • Days silent — how many days since the last payment. Small for a good payer, large for a stuck one.
  • Paid in 30 days — how much the client paid over the last month. Shows recent activity.
  • Average payment in 90 days — average payment size over the last 3 months. Gives a sense of the typical instalment the client makes.
{# 11. Suppliers #}

{# 14a. Sale markup presets #}

{# 15. Pocket Price #}

18. Pocket Price — public price list

Pocket Price is a lightweight page for viewing current prices and stock levels. It is designed for clients or staff who need to quickly look up a price without accessing the main ERP.

How to access:

  • The page is available at /price?token=<your_token>.
  • Tokens are created in Admin → Price Tokens: click «Create token», then copy the generated link and send it to the client or staff member — no ERP password needed.

Features:

  • Search products by name, model or barcode.
  • Scan barcodes with a phone camera (HTTPS required).
  • View sale price; optionally show stock quantity and purchase price — configurable per token.
  • Works as a PWA: can be «installed» on a smartphone home screen.

Security: anyone with the link can view the price list — do not share the token with unauthorised people. Tokens can be revoked or deleted in Admin → Price Tokens.

{# 16. Pocket Catalog #}

19. Pocket Catalog — mobile catalogue

Pocket Catalog is a PWA for working with the product catalogue on the warehouse floor. Staff can scan barcodes and update purchase prices without logging into the main ERP.

How to access:

  • The page is available at /catalog?token=<your_token>.
  • Tokens are created in Admin → Catalog Tokens.
  • On the first visit the device is bound to the token — no further login is needed, but another device with the same token will be rejected (prevents token leaks).

Features:

  • Look up products by barcode: manual entry, phone camera scan, or a hardware Bluetooth/USB HID scanner.
  • View product card: brand, model, name, stock balances.
  • Update the purchase price directly from the catalogue.
  • Add a new product to the catalogue without accessing the main ERP.

Hardware barcode scanner: Pocket Catalog works with an external scanner that connects to the phone as a keyboard — Bluetooth HID / Keyboard mode. Place the cursor in the barcode input field, scan the product — the scanner types the code into the field. If the scanner has an Enter suffix enabled, Pocket Catalog processes the code automatically; otherwise press the → button manually.

Scanner selection tips:

  • For a phone, choose a scanner that supports Bluetooth HID / Keyboard mode.
  • Scanners with only 2.4G USB are typically better suited for PCs and may require a USB dongle or OTG adapter.
  • Recommended option: a 2D Bluetooth HID scanner.
  • Desirable supported codes: EAN-13, EAN-8, UPC, Code128, plus QR / DataMatrix for versatility.
  • An Enter suffix is convenient but not required — without it you can press the → button manually.

Typical use case: a warehouse worker scans incoming goods, checks balances, and updates the purchase price — without interrupting the office manager.

Security: the token is bound to a specific device. To change devices or revoke access use Admin → Catalog Tokens.

20. Telegram bot

⚠️ Web edition only. The bot works together with this server-hosted web ERP. The desktop HASAPCY edition has no bot — it runs standalone on the customer's computer, without internet and without Telegram.

The bot is built for a single job — quick client-debt work on the go, when you're standing next to a client with your phone in hand. Products, stock, receiving, sales are not in the bot — those flows are much better in the web UI.

Commands:

  • /start — main menu: recent clients (active in the last 7 days) + search + top debtors
  • /clients — same as /start
  • /debt — total outstanding debt owed to you
  • /top_debtors — top 10 debtors with «days since last payment»
  • /expense — quick expense wizard (fuel, porter, rent, personal…)
  • /expenses_today — how much I spent today
  • /income — quick service-income wizard (PC repair, PlayStation, software…)
  • /income_today — how much I earned on services today
  • /help — short cheat sheet
  • /cancel — cancel the current step

Typical «in the field» flow — 3 taps:

  1. Open the bot → tap a client name in the recent list (or «🔍 Search» → part of the name → tap).
  2. On the client card (name, debt, phone, last 3 operations) tap a quick-pay button [💵 50/100/200/500]. For any other amount — «Other payment» → type the number.
  3. Confirm — «✅ Yes, apply». Done.

Adding debt:

  1. On the client card tap «➕ Add debt».
  2. Type the amount.
  3. Type a note — required (reason: «took goods on credit», «prepayment didn't arrive»). Without a note the bot won't save it, so you'll always know what the debt was for.
  4. Confirm — «✅ Yes, add debt».

Notes (matches web behaviour): payment note is optional (the bot doesn't even ask, to keep it fast); debt note is mandatory.

Web integration: every bot action is the same client_ledger row that web writes. Client balance, the DEB counter in the top-right of the web menu, the client's history — all update instantly. Open the client's history in the web UI and you'll see rows made via Telegram mixed in with the manual ones.

Who can use it: only the owner (via ADMIN_ID in the server config). If someone else finds the bot and sends /start — they get «Access denied».

What the bot deliberately doesn't do: add products, receives, stock, sales, invoices, reports, inventory, expenses. All of that already works well in the web UI — duplicating it would be pointless. Complex forms with products and prices on a phone touchscreen are just painful.

22. Background images

Main site background

The main background is used on all pages of the Hasapcy web interface: products, stock, receive, move, sale, return, reports, clients, suppliers, invoices, history, admin, and help.

File: app/web/static/bg.jpg

To replace it go to Admin → Settings → Background Image.

Recommended size for desktop: 1920 × 1080 px (16:9 ratio)

Also suitable: 2560 × 1440 px, 3840 × 2160 px

Tip: use a landscape (horizontal) image — the main interface is most often opened on a PC, laptop, or tablet. A dark or neutral background improves readability of tables and text.

Pocket Price background

Pocket Price uses a separate background image.

File: app/web/static/price-bg.jpg

To replace it go to Admin → Settings → Pocket Price Background.

Recommended size for mobile: 1080 × 1920 px (9:16 ratio)

Also suitable: 1440 × 2560 px, 720 × 1280 px

Tip: use a portrait (vertical) image — Pocket Price is usually opened on a phone. A not-too-bright background is better since product cards and prices are displayed on top of it.

File name and format

When uploading through the admin panel the original file name does not matter — you can upload a file with any name, for example shop-background.png or pocket-mobile.webp. The system saves the images to the correct files automatically:

  • bg.jpg — main background
  • price-bg.jpg — Pocket Price background

Supported formats: .jpg, .jpeg, .png, .webp, .gif

For best loading speed: .jpg or .webp is recommended.

File size

Very large images may slow down page loading. It is recommended to keep the file size roughly within 500 KB — 2 MB.

Updates without Ctrl+F5

After recent changes the background updates immediately after uploading a new image via the admin panel — no manual cache clearing and no Ctrl+F5 needed.

{# 18. Tips #}

23. Tips & common mistakes

  • ✅ Always finish an operation with the «Finish» button — an unfinished receive or sale does not affect stock balances.
  • ✅ Before making a sale, confirm the product is in stock — the system will not allow selling more than what is available.
  • ✅ Use barcodes — this speeds up adding products to an invoice and eliminates mistakes.
  • ✅ Make regular database backups via Admin → Backup.
  • ⚠️ Do not delete products that have already appeared in sales — archive them instead.
  • ⚠️ If stock balances seem off after cancelling an invoice — check the history: there may be another operation involving the same product.
  • ⚠️ Internet is required. If the page does not load — check your connection.
